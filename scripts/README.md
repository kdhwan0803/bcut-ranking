# 모델 페이지 갱신

`data.json`의 작품 정보나 공개일을 갱신한 뒤 저장소 루트에서 실행합니다. Node.js의 기본 기능만 사용하며 별도 패키지 설치는 필요 없습니다.

```sh
node scripts/update-model-pages.cjs
node scripts/check-model-pages.cjs
```

생성기는 한국시간의 오늘을 기준으로 공개 작품과 예정작을 구분합니다. 제목, 검색·공유 메타, 소개, FAQ, 구조화 데이터, 작품 목록과 최신작 버튼을 같은 데이터로 생성합니다. 아래 자동 배포가 생성된 HTML을 함께 공개하므로 검색 정보도 같은 데이터로 갱신됩니다.

## 자동 생성·검증·배포

GitHub Pages의 Source를 **GitHub Actions**로 설정합니다. `.github/workflows/catalogue-pages.yml`은 `main` 변경 때 모델 페이지를 생성하고 검증한 뒤 `_site` 결과를 배포합니다. PR에서는 같은 검사를 수행하며 배포하지 않습니다. `main`에서는 원본 `data.json`이나 썸네일을 수정하면 됩니다. 생성 결과를 저장소에 직접 커밋할 필요가 없습니다.

이미 데이터에 등록된 예정작의 공개일 전환을 위해 매일 한국시간 00:17에 실행합니다. GitHub 예약 실행은 지연될 수 있습니다. 새 작품 정보 자체를 판매 사이트에서 자동 수집하지는 않습니다. Actions의 **Build and deploy catalogue → Run workflow**로 즉시 실행할 수도 있습니다.

모델 제목·작품 수·최신작 링크·구조화 데이터·로컬 이미지 파일과 반복 생성의 안정성을 검사합니다. 검사가 실패하면 배포 단계가 실행되지 않아 이전 정상 배포가 유지됩니다. 구매 완료 이벤트나 시범 버튼의 배치는 변경하지 않습니다.

사이트맵은 마지막 정상 배포의 `sitemap-state.json`과 페이지 내용·참조 파일의 해시를 비교합니다. 실제로 달라진 페이지만 한국시간 수정일을 갱신하고, 같은 내용을 재배포하면 이전 수정일을 유지합니다. 보조 추천 모델의 작품 수만 바뀐 경우는 제외합니다. 이 상태 파일에는 공개 URL·해시·수정일만 있습니다. 최초 전환 때는 Git의 페이지·참조 파일 변경 이력으로 기존 사이트맵 날짜를 보정합니다. 상태 파일이 없는 404는 최초 전환으로 처리하며, 그 외 통신·형식 오류는 배포를 중단합니다.

로컬 검증은 깨끗한 체크아웃에서 실행합니다.

```sh
node scripts/check-sitemap.cjs
node scripts/build-site.cjs --offline
```

`--offline`은 최초 전환 검증용이며 실제 배포는 공개된 이전 상태 파일을 읽습니다. 이전 결과를 지정하려면 `--previous <sitemap-state.json 경로>`를 사용합니다. 빌드는 `_site`가 이미 있으면 덮어쓰지 않으므로 다음 빌드는 새 체크아웃을 사용합니다. 배포 파일에는 추적된 공개 파일만 포함하고 Git·워크플로·빌드 스크립트·로컬 임시 파일은 제외합니다.

날짜 경계 확인이 필요하면 두 명령에 같은 `--date YYYY-MM-DD`를 붙입니다. 미래 날짜로 확인한 뒤 실제 반영 전에는 위 명령을 다시 실행합니다.

브라우저는 매분과 탭 복귀 때 정보를 갱신합니다. 서버의 정적 HTML은 생성기를 실행하여 배포할 때 갱신됩니다. 썸네일 파일 교체는 기존 `img` 필드와 파일 경로를 사용합니다.

## 썸네일 실패 처리와 점검

`thumbnail-fallback.js`는 홈·이상형 월드컵·모델 페이지·모델 목록의 이미지 로드 실패를 감지하여 내장 대체 이미지로 표시합니다. 별도 이미지 요청 없이 카드 크기·제목·배지·작품 이동을 유지합니다. 아직 로드하지 않은 지연 로딩 이미지는 실패로 처리하지 않습니다. 자동 정보 갱신 시에는 원래 경로를 비교하여 같은 실패 이미지를 반복 요청하지 않고, `img` 경로가 바뀌면 새 썸네일을 정상적으로 로드합니다.

`https://bcutrank.com/thumbnail-check.html`에서 모델명·작품 번호로 대상을 찾고 **대상 점검 시작**을 누릅니다. 브라우저가 원래 썸네일을 한 번에 4개씩 실제 이미지로 로드하여 정상·로드 실패·시간 초과를 구분합니다. 결과에는 작품 번호·모델·제목·원래 이미지 링크가 있으며 실패 목록을 복사할 수 있습니다. 시간 초과는 일시적인 연결 문제일 수 있으므로 다시 점검합니다. 중지한 요청은 미점검으로 남습니다. 검색엔진에는 색인하지 않으며 분석 태그·자동 점검·외부 결과 전송·카탈로그 수정은 없습니다. 결과는 현재 화면에만 유지됩니다.

박서이 페이지는 첫 화면 속도 개선을 시범 적용합니다. 최신작 카드 CSS를 HTML에 포함하고, 외부 글꼴 CSS는 첫 화면 렌더링 후 적용합니다. `font-display: optional`을 사용하므로 느린 연결의 첫 방문에서는 기본 글꼴이 유지될 수 있고, 이미 캐시된 글꼴은 기존 글꼴로 표시됩니다. JavaScript가 꺼진 경우에도 글꼴과 정적 정보가 표시됩니다. 첫 데이터 조회는 페이지 로드 후 여유 시간에 실행하며, 이후 갱신 주기는 유지합니다. 내용이 같은 모델 목록·소개·FAQ·최신작 카드는 DOM을 다시 만들지 않아 이미지 로딩과 포커스를 유지합니다.

## 모델 페이지 이동 시범 개선

동그란(`donggeuran`), 슬이(`seuli`), 박서이(`bakseoi`)에는 최신 공개 화보 카드와 B컷 직접 이동 버튼이 적용됩니다. 위 생성기를 실행하면 이 카드도 같은 공개 데이터로 갱신됩니다. 브라우저는 기존 모델 데이터 요청 한 번으로 카드와 최신작 버튼을 함께 갱신합니다.

시범 페이지의 B컷 이동은 `go_bcut` 이벤트로 기록합니다. `module_id=model_cta_pilot_v1`, `work_id`, `link_origin`으로 작품과 클릭 위치를 구분합니다. 작품 정보 열기는 `model_work_open`, 페이지 진입은 `model_pilot_view`입니다. 기존 자동 외부 링크 `click`과 합산하지 않습니다. 시범 페이지의 기존 `model_cta_click`·`model_top3_click` 인라인 호출은 통합 이벤트로 대체합니다.

관리·미리보기·검사 링크(`admin=1`, `preview=1`, `measure=1`), 로컬 파일과 로컬 호스트에서는 GA를 전송하지 않습니다. 구매 완료 이벤트는 생성하지 않습니다. 직접 이동 버튼에는 `utm_source=bcutrank`, `utm_medium=model_latest`, `utm_campaign=model_cta_pilot_v1`을 사용합니다. 기존 인기작·모델 전체 링크와 UTM은 유지합니다.

## 홈 검색·목록 복원·계산 비용 개선

홈과 ‘찾아보기’ 검색창에 모델명 일부를 입력하면 공개 화보가 있는 모델을 최대 6명 표시합니다. 정확히 일치하는 이름, 이름 앞부분 일치, 나머지 일치 순서로 정렬하고 같은 그룹에서는 이름순으로 표시합니다. 화보 수는 유효한 공개일과 공개 상태를 기준으로 계산하며 공동 출연자의 중복 이름을 제외합니다. 후보 링크는 기존 모델 페이지 매핑을 사용하고 검사용 플래그를 전달합니다. 아래 화살표로 첫 후보에 포커스를 옮기고 Tab으로 링크를 탐색할 수 있습니다. 제목·작가 검색과 기존 필터도 함께 사용할 수 있습니다. 결과가 없으면 검색어를 유지한 채 필터만 해제할 수 있습니다.

목록의 검색·필터·정렬·펼친 편수·스크롤 위치·검색 결과 포커스·추가 필터 열림 상태는 현재 브라우저 방문 기록에만 저장합니다. 상세창을 닫거나 모델 페이지에서 뒤로 돌아올 때 데이터와 카드가 표시된 뒤 복원합니다. 다른 주소의 저장 상태와 형식이 맞지 않는 값은 사용하지 않으며 검색어를 GA에 추가 전송하지 않습니다. 기존 모달 뒤로 가기와 미리보기 측정 차단을 유지합니다.

홈 외부 글꼴 CSS는 렌더링을 차단하지 않도록 비동기로 적용하며 JavaScript가 없는 경우에는 noscript 링크를 사용합니다. Anton은 font-display optional을 사용합니다. 카탈로그 준비 전에는 본문과 캐러셀을 숨기고 기존 로딩 안내를 표시하여 초기 내용 교체에 따른 이동을 줄입니다. 주간·월간 순위와 검색 선택지 계산은 현재 카탈로그 안에서 재사용하고 새 데이터 적용 시 초기화합니다. 주소가 같으면 history.replaceState를 반복하지 않습니다. scripts/check-home-browse.cjs는 공개 모델 후보·빈 결과 복구·방문 기록 복원·캐시 초기화를 검사하며 배포 빌드에 포함됩니다.

화면에서 숨긴 카탈로그 섹션은 기존 sc-if로 렌더링을 생략합니다. 특히 홈에서는 작가별 전체 화보 그리드를 만들지 않고 기존 미리보기 선반만 표시합니다. 각 메뉴로 이동하면 해당 목록을 만들며, 모델 순위·화보 순위 전환과 작품 상세의 관련 작품도 같은 표시 조건을 사용합니다. 공용 support.js와 이미지 파일은 바꾸지 않습니다. check-home-browse.cjs는 여섯 메뉴의 표시 조건과 로딩 중 목록 생략을 검사합니다.

## 대표 모델 목록 필터·정렬 시범 개선

기존 이동 시범 대상인 동그란(`donggeuran.html`), 슬이(`seuli.html`), 박서이(`bakseoi.html`) 세 페이지에 **전체 / 사진 / 영상 포함**, **최신순 / 인기순**을 적용합니다. 각 모델의 공개 작품을 기준으로 필터별 편수를 표시합니다. 사진·영상 구분은 기존 카드 배지와 같은 `vid` 필드를 사용합니다. 인기순은 홈 검색과 같이 등록된 주간 랭킹에서 작품의 역대 최고 순위를 사용하며, 동률과 순위 기록이 없는 작품은 공개일·작품 번호의 최신순으로 정렬합니다. 미래 주차 기록은 사용하지 않습니다. 예정작은 공개 목록 필터에 포함하지 않습니다.

생성기가 목록과 필터용 데이터·CSS를 정적 HTML에 포함합니다. JavaScript가 꺼져 있으면 기존 전체 목록이 표시됩니다. 필터·정렬은 기존 카드 노드를 숨기거나 이동하여 실행하고 별도 데이터 조회를 하지 않습니다. 기존 분 단위 갱신에서 선택한 조건·키보드 포커스·실패 썸네일을 유지하며, 실제 작품 정보나 이미지 경로가 바뀐 카드를 갱신합니다. 제목·전체 편수·FAQ·최신작 버튼은 전체 공개 작품 기준을 유지합니다. `scripts/check-model-browse.cjs`는 배포 빌드에 포함됩니다.

효과 비교는 국내 네이버·구글 검색 방문 등 동일한 범위에서 B컷 이동이 발생한 세션 비율을 사용합니다. 여러 번 누른 클릭 수를 방문 세션으로 나누지 않습니다. 구매 효과는 판매 사이트 데이터와 별도로 연결해 확인합니다.

사용자가 실제로 조건을 바꾸면 `model_browse_change`를 한 번 기록합니다. `change_type`은 `format`·`sort`·`reset`이며 `model_slug`, `browse_format`, `browse_sort`, 이전 조건과 표시 편수를 포함합니다. 초기 진입·같은 조건 재클릭·자동 갱신·뒤로 가기로 복원하는 행동에는 변경 이벤트를 보내지 않습니다. 목록 카드의 기존 `model_work_open`에 선택 조건을 추가하며, 그 링크로 열린 같은 작품 상세에서 B컷 버튼을 누르면 기존 이름인 `go_bcut`에 조건과 `link_origin=work_detail`, `browse_origin=work_list`를 기록합니다. 다른 작품을 새로 열면 이 출처를 이어 붙이지 않습니다. 기존 직접 이동의 `go_bcut`·홈 추천 실험 이벤트와 자동 외부 링크 `click`은 각각의 목적에 따라 구분하여 분석합니다.

목록의 주소는 `format=photo|video`, `sort=popular`로 현재 조건을 유지합니다. 기본값인 전체·최신순은 생략합니다. 새로고침·뒤로/앞으로 가기·공유 링크 진입 시 조건을 복원하며, 잘못된 값은 전체·최신순으로 처리합니다. **목록 링크 복사**는 `#model-browse`가 포함된 현재 조건의 주소를 복사하고 검사 전용 `admin`·`preview`·`measure`만 제거합니다. 복사가 실패하면 주소창의 링크를 복사하도록 안내합니다. 기존 다른 쿼리 값은 보존합니다. 작품 링크의 `mb_model`·`mb_format`·`mb_sort`는 세 시범 모델과 허용된 조건만 상세 측정에 사용하며, 작품이 해당 모델의 작품인지 다시 확인합니다. 미리보기의 작품 이동은 검사 플래그를 전달하여 GA 전송 차단을 유지합니다.

## 작품 상세의 다른 화보

작품 상세의 ‘이 모델의 다른 화보’에는 현재 작품을 제외하고 같은 모델이 참여한 공개 화보를 최근 공개순으로 최대 8편 표시합니다. 공동 출연 작품은 중복을 제거합니다. 예정작·비공개·유효하지 않은 공개일은 제외하며, 제목·공개일·사진/영상 포함 표시와 실제 작품 정보 링크를 제공합니다. 모델별 전체 목록 링크는 생성기가 모델 목록의 슬러그 설정과 실제 페이지 파일을 확인하여 갱신합니다. 모바일에서는 두 열 카드로 표시하며 기존 구매 버튼과 썸네일 실패 처리는 유지합니다. `scripts/check-work-detail.cjs`가 배포 빌드에서 공개 조건·정렬·모델 연결과 실제 상세 화면 데이터를 검사합니다.
